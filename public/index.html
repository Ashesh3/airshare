A new AirShare

AirShare brings browser and terminal file transfers to a self-hosted, open-source app. It keeps the familiar live-streaming workflow, gives you control of the relay, and supports large files and multiple receivers without saving file contents on the server. Features include:

  • Fast streaming with backpressure and bounded memory
  • Separate sender and receiver links
  • Receiving a file from your terminal
  • Sending to multiple receivers at once
  • QR codes for sharing with another device
  • Links that survive a server restart while the sender stays connected

Keep the sender tab or terminal running during the transfer. File contents are never stored on the server, and no application file-size limit is configured by default.

AirShare is independent open-source software. Visit the project for source code, feedback, and self-hosting instructions.

Use AirShare to send and receive files from your terminal

Sending files

Sending a file with cURL 
curl -T myfile.zip -s -L --max-redirs -1 -D - {{origin}} | grep human
Sending a file with Wget 
wget --post-file=myfile.zip --max-redirect=1000000 -S -O - \
  {{origin}}/myfile.zip 2>&1 | grep human

Share one of the two URLs it prints, or let the other person scan the QR code. Keep the command running to host the file. Press CTRL+C to stop.

Receiving files

Receiving a file with cURL 
curl -s -J -O -L -D - {{origin}} | grep human
Receiving a file with Wget 
wget --content-disposition -S -o - {{origin}} | grep human

Send one of the two printed URLs to the person who has the file. They can open the page, or run curl -T <file> <URL>. For folders, encrypted output and other piped input, see the recipes.

Recipes

Pipes & cURL

Pipes cannot be replayed, so a one-line … | curl -T - {{origin}}/name is answered with these two steps instead of sending. Preparing prints the links to share and a QR code; the second command then sends the stream once.

Sending a folder

UPLOAD_URL=$(curl -fsS -X POST -D /dev/stderr \
  "{{origin}}/xfr/folder.tar.gz?prepare=1")
tar -czf - ./folder | curl -fS -T - "$UPLOAD_URL"

Sending encrypted output

UPLOAD_URL=$(curl -fsS -X POST -D /dev/stderr \
  "{{origin}}/xfr/payload.gpg?prepare=1")
gpg --encrypt -o - --recipient recipient@example.com ./file \
  | curl -fS -T - "$UPLOAD_URL"

Sending a process dump

UPLOAD_URL=$(curl -fsS -X POST -D /dev/stderr \
  "{{origin}}/xfr/stack.txt?prepare=1")
jstack <process-id> | curl -fS -T - "$UPLOAD_URL"

Use a POSIX shell for these examples. For binary native pipes on Windows, use PowerShell 7.4+ or cmd.exe. A stream is available once; regular files can stay hosted for repeated downloads.

About

AirShare is an independent, open-source live file relay for browsers and terminals.

Choose a file, share its link, and keep the sender connected while the recipient downloads. Data streams through your server without saving file contents to disk.

How sharing works

A browser share lasts while its tab stays open. Moving between Home, Recipes, About and the other pages keeps it going; closing or reloading the tab ends it, and anyone still waiting is told that the sender stopped sharing. Several people can download the same file, and links keep working across a relay restart while the sender stays connected. From a terminal, the file is available while the command runs.

Self-hosted file transfers

Run the relay near your devices and use HTTPS for Internet transfers. The sender's upload, the relay's connection, and the recipient's download determine transfer speed.

Source code and setup instructions are available on GitHub. AirShare is not affiliated with Station307.

Privacy

AirShare relays file contents live and does not save them on the server. The relay can observe the contents; transport encryption is not end-to-end encryption.

The database never stores share links in readable form: only their one-way SHA-256 hashes, plus encrypted copies that only the link one level up can open. It also keeps each file's name, size and type, timestamps, transfer counts and a hashed client IP address for quotas. Keep the metadata volume and owner and sender links private.

This site stores nothing in your browser: no cookies, local storage or other site data. Your list of shared files exists only in the open tab.

A browser share ends when you close or reload its tab. Its link stops working shortly afterwards, and anyone still waiting is told that the sender stopped sharing. Terminal and API links remain until their configured expiry, so a returning sender can resume hosting. Your instance's operator controls its configuration and any proxy logging.
